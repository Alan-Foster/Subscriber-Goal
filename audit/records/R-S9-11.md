# R-S9-11: Core and crosspost classify 'post is gone' errors in opposite ways

**Problem · suspected** · criticality 6/10 · areas 9.05, 9.02, 10.10, 6.06 · paths C7-crosspost-dispatch, C7-moderation-mirror, C6-deletion-verification, C5-queued-post-update

## 1. Current Implementation

Core code treats only HTTP 404/410, NOT_FOUND/GONE codes and two exact messages as 'missing', so Devvit's gRPC 13 'post not found' is retried forever (R-W6-01). Crosspost code treats any message containing 'not found', 'does not exist', 'deleted' or 'no longer exists' as permanent, so an unrelated transient error with one of those words ends a crosspost action for good.

## 2. Problem and evidence

Three crosspost sites use /not[\s-]?found|does not exist|deleted|no longer exists/i on the error text. Messages like 'subreddit not found' during an outage, or an error about a deleted user, would match. Core uses status codes plus a pattern tied to the post id.

**Location:** src/server/core/postRetirement.ts:31 (classifyPostLookupError); src/server/crosspost/pending.ts:44 (isMissingSourcePostError); src/server/crosspost/moderation.ts:118; src/server/crosspost/ingestion.ts:228

**Observed outcome:** The core side is confirmed in production (R-W6-01). The crosspost side has not been observed.
