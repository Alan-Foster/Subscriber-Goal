# R-W5-01: One subscriber-count read can end onboarding permanently

**Problem · suspected** · criticality 7/10 · areas 4.04, 6.06, 10.09

> Audit record. Generated from `audit/records/R-W5-01.json` by `npm run audit:records`; edit the JSON, not this file. To turn it into an issue, follow `audit/issue-template.md`.

## 1. Current Implementation

If getCurrentSubreddit() returns fewer than 1,000 subscribers (or a stale, zero or missing count), onboarding saves itself as complete/ineligible and is not retried until the next install or upgrade.

## 2. Problem and evidence

Eligibility uses a single numberOfSubscribers read; !(NaN >= 1000) is also true. The subscriber_count reason is explicitly excluded from 'uncertain', so it never defers or retries. Only lifecycle reconciliation on install or upgrade re-arms onboarding.

**Location:** src/server/core/onboardingEligibility.ts:24; src/server/core/onboardingSubscriberGoal.ts:865
