# R-S9-04: Moderator erasure by user ID may leave the user's name in recent subscribers while reporting success

**Problem · suspected** · criticality 7/10 · areas 9.08, 6.07, 5.07 · paths C2-erase-other-user

> Audit record. Generated from `audit/records/R-S9-04.json` by `npm run audit:records`; edit the JSON, not this file. To turn it into an issue, follow `audit/issue-template.md`.

## 1. Current Implementation

When the moderator erase form resolves a user ID (directly, or by looking up a username), the route calls untrackSubscriberById only and shows 'erase success'. The username-based recent-subscriber cleanup (eraseFromRecentSubscribers) runs only on the partial-erase branch. Self-erasure, by contrast, calls both.

## 2. Problem and evidence

untrackSubscriberById calls eraseSubscriberOrdersById (order records by user ID) and clears subscriber stats. Recent-subscriber display fields are indexed by username in recentSubscriberPostsByUsernameKey and are removed by eraseFromRecentSubscribers, which this branch never calls. Whether eraseSubscriberOrdersById also clears those display fields is unverified.

**Location:** src/server/routes/internalUi.eraseData.ts:164 (untrackSubscriberById branch); src/server/data/subGoalData.ts:1230 (eraseFromRecentSubscribers); src/server/data/subscriberStats.ts:153 (untrackSubscriberById)

**Observed outcome:** Not observed.

**Unverified assumptions:**

- That eraseSubscriberOrdersById does not already remove the username-indexed display fields.

## 3. Required behavior and scope

The erase-success toast only after every store that holds the user's data is cleared; otherwise the partial toast.
