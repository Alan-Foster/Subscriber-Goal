# R-S9-15: Corrupt numeric goal fields parse to NaN or 0 with no log

**Problem · suspected** · criticality 5/10 · areas 5.01, 9.03, 5.09, 6.03 · paths C5-completion-detection, C5-autogoal-successor, C5-queued-post-update

> Audit record. Generated from `audit/records/R-S9-15.json` by `npm run audit:records`; edit the JSON, not this file. To turn it into an issue, follow `audit/issue-template.md`.

## 1. Current Implementation

getSubGoalData reads completedTime with parseInt when the field is non-empty; a corrupt or partial value becomes NaN, which every check treats as 'not completed'. The AutoGoal failure counter is read with Number(raw) || 0, so a corrupt counter silently restarts at 0.

## 2. Problem and evidence

`completedTime: stored.completedTime ? parseInt(stored.completedTime) : 0` has no validation or log, unlike the goal field (parsePersistedSubscriberGoal) and the suppression field, which logs stored_state_conflict. A NaN completedTime makes a completed goal look unfinished, and makes AutoGoal's source check fail (R-W5-07 cancels the successor silently). A counter reset defeats the retry cap (see #206).
