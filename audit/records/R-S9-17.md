# R-S9-17: Install/upgrade onboarding reconciliation is skipped for good when the community lease is busy

**Problem · suspected** · criticality 6/10 · areas 3.02, 6.01, 7.04, 4.03 · paths C5-upgrade, C5-install

> Audit record. Generated from `audit/records/R-S9-17.json` by `npm run audit:records`; edit the JSON, not this file. To turn it into an issue, follow `audit/issue-template.md`.

## 1. Current Implementation

If the community-wide lease is held when the install or upgrade trigger runs, reconcileOnboardingForLifecycle returns { status: 'unchanged', reason: 'community_mutation_in_progress' }. onAppChanged reports only the status; the reason is dropped, and nothing retries the reconciliation until the next install or upgrade.

## 2. Problem and evidence

The posts-updater job takes the same lease every minute (R-S7-01), so an upgrade landing during a job run is a realistic collision. reportLifecycleOnboardingState receives reconciliationStatus but not reconciliation.reason.

**Location:** src/server/core/onboardingLifecycle.ts:99 (busy lease → unchanged); src/server/triggers/appChanged.ts:127 (status kept, reason discarded)

**Observed outcome:** Not observed.

**Unverified assumptions:**

- That the upgrade trigger isn't re-delivered by Devvit after a successful (200) response.
