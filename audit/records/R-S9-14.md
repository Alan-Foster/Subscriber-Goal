## 1. Current Implementation

useSubGoalLoading turns request failures into an error state, but if runInit throws unexpectedly, the outer catch only logs to the browser console. loading stays true and no error is set, so the skeleton never goes away.

## 2. Problem and evidence

The .catch calls logDiagnostic and nothing else; setLoading(false) and setError run only inside runInit's own branches. requestJsonWithRetry returns failures as results, so this needs a throw from elsewhere (for example a header helper or a state setter).
