# R-S8-01: Legacy postsUpdaterJob cron from the Devvit Blocks version may still fire unseen

**Problem · suspected** · criticality 5/10 · areas 8.01, 8.08, 12.03, 13.01, 13.09 · paths C8-posts-updater-run

> Audit record. Generated from `audit/records/R-S8-01.json` by `npm run audit:records`; edit the JSON, not this file. To turn it into an issue, follow `audit/issue-template.md`.

## 1. Current Implementation

The app never lists or cancels scheduled jobs. Installations that ran the pre-Devvit Web version may still have a runtime cron named postsUpdaterJob firing every minute with no matching task, so nothing appears in the app's logs.

## 2. Problem and evidence

The Devvit 0.15 scheduler docs say a job created with scheduler.runJob({ name, cron }) keeps its stored schedule until the app cancels it. The Devvit Web migration (4783d61, 2026-01-26) replaced the job with the devvit.json task posts-updater-job but never cancelled the old runtime job. Characteristics: B, C, E.

**Location:** devvit.json (scheduler.tasks has no postsUpdaterJob task); created by _original/src/triggers/appChanged.ts:19 at commit 4783d61^ via startSingletonJob(context.scheduler, 'postsUpdaterJob', '* * * * *', {}); no listJobs or cancelJob anywhere in src/

**Observed outcome:** Not observed. Needs a scheduler.listJobs() inventory on a real installation; the Devvit CLI has no command for it.

**Unverified assumptions:**

- That the old job still exists on some installations (only an inventory can confirm).
- That it would show as MANAGER_UNSPECIFIED.
