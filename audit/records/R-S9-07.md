# R-S9-07: Due-job entries with no matching worker are skipped silently and never cleared

**Problem · suspected** · criticality 4/10 · areas 7.09, 8.02, 4.02, 13.03 · paths C8-job-runner, C6-app-repair, C6-scheduled-post-displacement

> Audit record. Generated from `audit/records/R-S9-07.json` by `npm run audit:records`; edit the JSON, not this file. To turn it into an issue, follow `audit/issue-template.md`.

## 1. Current Implementation

dispatchDueJobs reads up to 25 due members from the shared due-jobs index. A member whose job id isn't in the current run's worker list is skipped with `continue` and no log, and stays in the index.

## 2. Problem and evidence

Each caller passes only the workers it runs: dispatchScheduledJobs omits scheduled-post displacement when there's no subreddit, and onboarding and AutoGoal dispatch alone. Members of job types that were renamed or retired in earlier versions would also stay forever. Every skipped member still uses one of the 25 batch slots on every run.

**Location:** src/server/jobs/runner.ts:107 (if (!job) continue;); src/server/jobs/runner.ts:21 (batchSize = 25)
