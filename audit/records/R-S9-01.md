# R-S9-01: Source-post deletion verification retries silently until it gives up

**Log gap** · criticality 6/10 · areas 9.05, 7.08, 13.06, 6.06 · paths C6-deletion-verification, C6-delete-goal

> Audit record. Generated from `audit/records/R-S9-01.json` by `npm run audit:records`; edit the JSON, not this file. To turn it into an issue, follow `audit/issue-template.md`.

## 1. Current Implementation

When verifying a deletion finds the post still live or the lookup inconclusive, reschedule() saves a new attempt with no log line. Only the final exhausted attempt logs source_post_deletion_attempts_exhausted, and the intent then becomes terminal_failed.

## 2. Problem and evidence

reschedule() calls saveSourcePostDeletionIntent and logs only when retry.exhausted. Its callers pass reasons such as 'source_still_live' and 'source_lookup_inconclusive' that never reach the logs. Combined with R-W6-01 (a post the app deleted still reads as active), verification can retry silently for the whole retry budget and end terminal_failed, leaving the goal registered.
