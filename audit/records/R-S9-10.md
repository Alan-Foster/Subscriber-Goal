# R-S9-10: An unpin with no moderator name skips the scheduled-post displacement check silently

**Problem · suspected** · criticality 5/10 · areas 3.06, 3.08, 10.05, 4.10 · paths C6-mod-action, C6-scheduled-post-displacement

> Audit record. Generated from `audit/records/R-S9-10.json` by `npm run audit:records`; edit the JSON, not this file. To turn it into an issue, follow `audit/issue-template.md`.

## 1. Current Implementation

For an 'unsticky' mod action on an app post, the displacement check is recorded only when event.moderator.name is present and isn't the app. Without a moderator name, the handler returns with no log, so the goal may not be re-pinned after a scheduled post displaces it.

## 2. Problem and evidence

`const moderator = event.moderator?.name?.trim().toLowerCase(); if (moderator && ...)` then `return;`. The scheduled_post_displacement_unpin_received log at the top records hasActionedAt but not whether a moderator was present.

**Location:** src/server/triggers/modAction.ts:150 (unsticky branch of handleManagedPostModAction)

**Observed outcome:** Not observed.

**Unverified assumptions:**

- That Reddit sends unsticky events without a moderator for some displacement cases (scheduled posts, admin or system actions).
